## What This Package Does
`concrete` implements **continuous-time Targeted Maximum Likelihood Estimation (TMLE)** for cause-specific absolute risk estimands in right-censored survival settings with or without competing risks. It is published on CRAN and has an accompanying paper (arXiv:2310.19197).

Key statistical concepts: TMLE, Super Learner, cause-specific hazards, propensity scores, efficient influence curves, simultaneous confidence bands, competing risks, cumulative incidence.

## Architecture

### Core Workflow (Main Pipeline)

The package follows a three-step estimation pipeline:

1. **`formatArguments()`** (`R/formatArguments.R`) - Validates and formats input data, creates a `ConcreteArgs` object containing:
   - Formatted data.table with event times, types, treatment, covariates
   - Intervention specifications via `makeITT()` for intent-to-treat or custom functions
   - Cross-validation fold setup via `origami` package
   - Model specifications for propensity scores and hazards

2. **`doConcrete()`** (`R/doConcrete.R`) - Runs the TMLE estimation, returns `ConcreteEst` object:
   - Calls `getInitialEstimate()` for nuisance parameter estimation
   - Calls `getEIC()` to compute efficient influence curves
   - Calls `doTmleUpdate()` for one-step TMLE updates until convergence

3. **`getOutput()`** (`R/getOutput.R`) - Extracts final estimates, returns `ConcreteOut` object:
   - Computes absolute risks, risk differences (RD), relative risks (RR)
   - Provides both pointwise and simultaneous confidence intervals

### Internal Estimation Components

- **`getInitialEstimate.R`** - Orchestrates initial nuisance parameter estimation
- **`getPropScore.R`** - Treatment propensity score estimation using SuperLearner
- **`getHazEstimate.R`** - Cause-specific hazard estimation using Cox regression ensembles
- **`getEIC.R`** - Efficient influence curve computation for all target estimands
- **`doTmleUpdate.R`** - One-step TMLE fluctuation updates

### C++ Performance Code

`src/rcpp_getCleverCovariate.cpp` contains RcppArmadillo implementations for:
- `getCleverCovariate()` - Clever covariate calculation for EIC
- `getHazLS()` - Hazard integration helper
- `updateHazardsCpp()` - TMLE hazard update step

## Mathematical Reference

### Efficient Influence Curve (EIC)
For subject i, target event j, target time τ:
```
IC[j,τ](i) = pm(i) − integral(i) + F_j(τ,i) − mean_i[F_j(τ,i)]
```
- `pm(i)` = W[T̃_i,i] · (1{Δ_i=j} − h_FS(T̃_i,i)) · 1{Δ_i≠0, T̃_i≤τ}
- `integral(i)` = Σ_{t≤min(τ,T̃_i)} W[t,i] · (h_j[t,i] − h_FS(t,i)·h_total[t,i])
- `h_FS(t,i)` = (F_j(τ,i) − F_j(t,i)) / S(t,i) for t ≤ τ
- `W[t,i]` = g*(A_i|W_i) · NuisanceWeight[t,i]
- `h_total[t,i]` = Σ_l h_l[t,i]

### Convergence Criterion
Converged when for **all** target (j, τ):
```
|PnEIC[j,τ]| ≤ seEIC[j,τ] / (√n · log n)
```
where PnEIC = empirical mean of IC[j,τ], seEIC = √(mean(IC[j,τ]²)).

### Hazard Update Rule (one-step TMLE)
```
h_l^new(t,i) = h_l^old(t,i) · exp(ε · update_l(t,i))
```
Step size ε starts at `OneStepEps` (default 0.1) and halves if ‖PnEIC‖ increases.

### Key Invariants (must hold after any computation change)
- `h_l(t,i) ≥ 0` for all l, t, i (hazards are non-negative)
- `S(t,i) ∈ (1e-12, 1]` — survival bounded at floor 1e-12 by `boundSurvival()`
- `F_j(τ,i) ∈ [0,1]` and `Σ_j F_j(τ,i) ≤ 1` for all i, τ
- `mean_i[IC[j,τ](i)] ≈ 0` after TMLE convergence (empirical mean of EIC → 0)
- Nuisance weights ≥ `MinNuisance` (truncated in `truncNuisanceWeight()`)

### C++ ↔ R Reference Alignment
The C++ functions in `src/rcpp_getCleverCovariate.cpp` implement these formulas:
- `computeIC()` — implements the EIC formula above; key optimization: collapses L-hazard loop via `hTotal`
- `updateHazardsCpp()` — implements the update rule; uses reverse cumsum `psum` over target times
- `getIC()` in `R/getEIC.R` is the slower R reference implementation — **use it to verify C++ correctness**
  after any changes to `computeIC()` or `updateHazardsCpp()`

## Key Data Structures

- **`ConcreteEst`** - List of estimates per intervention with hazards, survival curves, EICs (class assigned in `doConcrete()`)

## Coding Standards

### R Code
- **Style**: Follow tidyverse style guide unless it contradicts existing style (eg use camelCase)
- **Documentation**: Every exported function gets full roxygen2 docs: `@title`, `@description`, `@param`, `@return`, `@examples`, `@export`
- **Internal functions**: Prefix with `.` or do not `@export`; still add roxygen `@keywords internal`
- **Vectorize** where possible; avoid explicit for-loops over observations
- **data.table**: This package uses `data.table` internally — use `:=`, `.SD`, `set()` idioms, not dplyr
- **Imports**: Prefer `@importFrom pkg fun` over `pkg::fun()` in hot paths; always declare in DESCRIPTION
- **No `library()` or `require()`** inside package code — ever

### C++ / Rcpp
- Source lives in `src/`; registered via `src/RcppExports.cpp` and `R/RcppExports.R`
- After editing C++ code, regenerate wrappers: `Rscript -e 'Rcpp::compileAttributes()'`
- Follow Rcpp best practices: use `NumericVector`, `NumericMatrix`, avoid raw `SEXP` manipulation
- Guard against NA/NaN inputs in C++ — R passes them through silently
- Keep C++ focused on tight numerical loops; orchestration logic stays in R

### Testing (testthat)
- Test files: `tests/testthat/test-<topic>.R`
- Use `testthat::test_that("description", { ... })` blocks
- Test both correctness (known-answer checks against hand-computed values) and edge cases (empty data, single-row, NA handling)
- Statistical tests: use reasonable tolerances (`expect_equal(..., tolerance = 1e-6)`)
- Snapshot tests for printed output of `print`/`summary` methods

### CRAN Compliance
- Zero ERRORs, zero WARNINGs from `R CMD check --as-cran`
- NOTEs should be minimized; "New submission" NOTE is acceptable
- No `T`/`F` — always `TRUE`/`FALSE`
- No `cat()` or `print()` in functions — use `message()` (which users can suppress)
- Examples must run in < 5 seconds or be wrapped in `\donttest{}`
- All Suggests packages must be guarded: `if (requireNamespace("pkg", quietly = TRUE))`

### Git & GitHub
- Branch naming: `feature/<name>`, `fix/<name>`, `release/<version>`
- Commit messages: imperative mood, concise (`Add penalized Cox SL candidate`, `Fix NA handling in getOutput`)
- PR workflow: branch → commit → push → open PR → CI green → merge
- Tag releases matching CRAN version: `v0.x.y`  

## Key Domain Knowledge
- **Nuisance parameters**: propensity scores (treatment mechanism) and conditional cause-specific hazards (outcome mechanism) — estimated via Super Learner
- **Targeting step**: one-step TMLE update using the efficient influence curve; produces doubly-robust, locally efficient estimates
- **Estimands**: cause-specific absolute risks (cumulative incidence), risk differences, risk ratios — at user-specified time points
- **Inference**: asymptotic normality via influence curve variance; simultaneous confidence bands across times/events
- **Current limitation**: Super Learner candidates must be Cox regressions (coxph backend)
